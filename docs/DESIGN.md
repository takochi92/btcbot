# 設計メモ（プロンプトの 00〜08 への答え）

元にしたのは「AI Trading Bot - Claude Opus 5.5 + Jev」というプロンプト画像です。
その手順に沿って、たこさんの答えに合わせた結論を書きます。

## 00. 聞き取りの答え

| 質問 | 答え |
|---|---|
| 資金 | お金は使わない（仮想売買のみ） |
| 取引先と銘柄 | 暗号資産（BTC） |
| 保有期間 | 数時間〜数日 |
| 判断の速さ | 数分かかってもよい |
| 許容できる最大下落 | 30% |
| 言語 | Python |

## 01. お金と速さの計算

判断は 1日1回（日足が確定したあと）。1回の判断に入力 3,000 トークン、出力 500 トークンと仮定します。

| やり方 | 1回あたり | 1か月（30回） |
|---|---|---|
| (a) Opus 5.5 が毎回判断（$4 / $20 per 100万トークン） | 3,000×$4/1M + 500×$20/1M = $0.022 | 約 $0.66 |
| (b) Jev が毎回判断（画像の値: 入力 $0.042/1M、出力無料） | 3,000×$0.042/1M = $0.000126 | 約 $0.004 |
| (c) プログラムだけで判断（今回の形） | $0 | $0 |

画像では (a) と (b) の差が約175倍になりますが、金額にすると月 $0.66 と $0.004 の差です。
判断の速さも、1日1回なら 70ms でも 30秒でも結果は変わりません。
**この使い方では、Jev を入れて得することは実質ありません。**
（Jev / TypeSafe AI の性能や料金は私の側では確かめられず、画像に書いてある数字をそのまま使っています。）

## 02. 勝ち筋（エッジ）

- 数ミリ秒を争う売買は、専用設備を持つプロ（マーケットメイカー等）の世界で、個人の資金と速さでは勝ち目がありません。だから最初から外します。
- 個人でも試す価値があるのは**トレンドフォロー**（上がり続けている間だけ持つ）です。暗号資産では「上がったものはしばらく上がり続けやすい」という研究があります。
- 相手側（負けている側）として考えられるのは、早く利食いしすぎる人や、下落中に「安い」と買い向かう人です。ただし、本当にまだ続いているかはわかりません。
- 現実的に期待できるのは「ガチホより儲かる」ことよりも、「大きな下落を避けて、同じくらいの成績をもっと小さな揺れで取る」ことです。
- **バックテストで合格しなければ、このアイデアは捨てる**と決めています（05）。

## 03. 判断の振り分け

| 判断 | 担当 | 理由 |
|---|---|---|
| 移動平均より上か下か | プログラム | ただの計算 |
| 損失上限・停止の判定 | プログラム | モデルに任せてはいけない |
| 手数料・資産の計算 | プログラム | ただの計算 |
| 仮説の設計・コードの見直し | Opus（開発時だけ） | 設計と見直し |

プロンプトの「売買を変えない質問は消す」に従うと、Jev に聞く質問は**1つも残りません**。
迷う判断（例:「今は荒れている相場か？」）を足すなら、それが売買をどう変えるかを先に決め、05 のバックテストを通してからにします。

## 04. 先生と生徒（Opus が教えて Jev が答える）

03 で Jev に渡す質問がなくなったので、**今回は作りません**。
将来、判断の質問を足すときは、過去の相場の場面を Opus に判定させ、Jev の答えと合わせ、実際の値動きと比べて（Brier スコア）、合っている種類の質問だけ使います。

## 05. 負けうるバックテスト

- 仮説と試す変種（20/50/100/150/200日）は `config.toml` に書き、`hypothesis.lock` で**データを見る前に固定**しました。変えるとバックテストが止まります。
- 先読みはしません（t日の終値で決めて、t+1日から持つ）。テストで確かめています。
- 手数料 片道 0.1%、ずれ 片道 0.05% を引きます。日足で成行なので、注文の順番待ち（キュー位置）は考えなくてよい扱いです。
- 時期を6つに分け、1つを検証、残りで変種を選びます。検証期間の前後200日は学習に使いません（移動平均を通じて値段が漏れるのを防ぐ）。
- 5つの変種を試したぶん、**デフレーテッド・シャープ比**で「運でよく見えた」分を差し引きます。
- 合格の条件: デフレーテッド・シャープ比 0.95 以上、検証区間の 67% 以上がプラス、最大下落がガチホより小さい。
- **結果は良くても悪くても `reports/backtest.md` にそのまま出ます。**

## 06. 実行とリスク

- 判断から約定までの遅れは、1日1回なので数分あっても構いません。
- 約定後の値動きは、1秒・10秒・60秒ではなく**1日後・3日後**を記録します（日足なので秒単位は意味がないため）。
- 安全装置は `btcbot/risk.py` にあり、設定ファイルでも上限より緩くできません。
  - ポジション: 資産の 100% まで（借金なし）
  - 1日の損失: 5% で手じまい（翌日に再開）
  - 連敗: 5回で停止
  - 最大下落: 30% で全部手じまいして停止
  - 古いデータ: 2日より古ければ新しく持たない
  - データ取得の失敗: 3回続いたら停止
- 停止ボタン: `python -m btcbot kill`、または GitHub の Actions 画面で paper-trade を kill=true で実行。

## 07. 本番のルール

- 今回は**仮想売買のみ**。本物のお金と取引所の鍵は使いません。
- 止まる条件は先に決めてあります: 仮想売買で10回以上売買したあと、1回あたりの平均がバックテストの下側95%限界を下回ったら、ボットは自分で止まります。
- すべての判断を `state/decisions.jsonl` に、状態と一緒に記録します。
- 「毎晩 Opus がログを見直して変更を提案する」は、まだ作っていません。変更するときは必ず新しい仮説として 05 をやり直します。

## 08. 作り

AgenKit は確かめられないので使っていません。Claude Code で「仕様 → テスト → コード → 見直し」の順に作りました。

```
config.toml           設定（仮説・検証・リスク・仮想売買）
hypothesis.lock       仮説の固定値
btcbot/
  data.py             BTC 日足の取得（Binance → だめなら Coinbase）
  strategy.py         移動平均シグナル
  backtest.py         バックテスト・時期を分けた検証
  stats.py            シャープ比・最大下落・デフレーテッド・シャープ比
  report.py           結果の判定とレポート
  risk.py             安全装置（上書き不可）
  paper.py            仮想売買
  cli.py              コマンド
tests/                テスト
.github/workflows/    テスト・バックテスト・毎日の仮想売買
```

### 進め方

1. 済: 仮説を固定し、テストとコードを用意
2. 済: GitHub Actions でバックテストを実行 → `reports/backtest.md`
3. 合格なら: 毎日 09:17（日本時間）に仮想売買が1回動き、`state/` に記録
4. 2〜3か月後: 仮想売買とバックテストを比べる。不合格ならアイデアを捨てるか、新しい仮説を固定してやり直す
